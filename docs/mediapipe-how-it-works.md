# การตรวจจับและแจ้งเตือนของระบบ MediaPipe

ระบบ MediaPipe ทำงานในเบราว์เซอร์ทั้งหมด ทุกเฟรมจึงแย่งเวลากับหน้าเว็บ
การออกแบบส่วนใหญ่ในเอกสารนี้ตอบคำถามเดียว คือจะตรวจให้ทันโดยไม่ทำให้หน้าเว็บหน่วง และไม่เตือนจนคนรำคาญได้อย่างไร

## ท่านั่ง หกล้ม และเตือนพัก

`PostureEngine` ใน `frontend/src/lib/postureEngine.ts` เป็นตัวจัดการงานนี้ หนึ่ง instance ต่อกล้องหนึ่งตัว

1. `usePoseLandmarker` โหลดโมเดล BlazePose 33 จุดรุ่นที่เลือกจากไฟล์ในเครื่อง ใช้ GPU delegate และเปลี่ยนไปใช้ CPU ถ้า GPU ใช้ไม่ได้
2. `lib/poseThrottle.ts` จำกัดการรันโมเดลไว้ที่ 12 fps ต่อกล้อง และรันเฉพาะเมื่อเฟรมวิดีโอเปลี่ยนจริง
3. `PostureEngine` ทำขั้นตอนเหล่านี้ทุกเฟรม
   - `lib/tracker.ts` จับคู่คนข้ามเฟรมให้มี trackId คงที่
   - `lib/postureAnalysis.ts` คำนวณมุมคอ มุมลำตัว มุมเอียงไหล่ และ `headHeightRatio` โดยข้ามจุดที่ visibility ต่ำกว่า `minVisibility`
     แล้วแยกว่ากล้องเห็นทั้งตัว (`full_body`) หรือเห็นแค่ช่วงบน (`upper_body`)
   - `lib/smoothing.ts` ทำค่าให้นิ่งด้วย EMA แล้ว `classifyPosture` จัดท่าเป็น forward_head, slouching, leaning หรือ good
     ถ้า Calibrate แล้ว `classifyPosture` ตัดสินจากส่วนต่างเทียบกับ baseline ของกล้องนั้น และจากสัดส่วนหัวที่ต่ำลง
   - `lib/fallDetection.ts` ตรวจการร่วงตัวเร็วและการหายจากเฟรม
   - `lib/breakReminder.ts` จับเวลานั่งต่อเนื่อง
4. `services/postureBaselineStore.ts` เก็บ baseline ท่านั่งใน localStorage แยกต่อกล้อง ด้วย key `camwell:posture-baseline:v1:<cameraId>`

การจำกัดที่ 12 fps แลกความถี่ของเฟรมกับเวลาว่างของหน้าเว็บ แต่ละรอบจึงมีเวลาประมาณ 83 ms
ท่านั่งเปลี่ยนช้ากว่าหนึ่งเฟรมมาก การแลกนี้จึงเสียความแม่นยำของท่านั่งน้อยมาก

## ความเหนื่อยล้า ระยะห่างจากจอ และการระบุตัวตน

1. `useFaceApiModels` โหลดโมเดล TinyFaceDetector, FaceLandmark68 และ FaceRecognition จากไฟล์ในเครื่อง
2. `CameraStage` ตรวจใบหน้าทุก 400 ms ไม่ใช่ทุกเฟรม แล้วจับคู่ใบหน้ากับคนจาก pose ที่อยู่ใกล้ที่สุด
3. `lib/fatigueAnalysis.ts` คำนวณ EAR สำหรับตาหลับ และ MAR สำหรับการอ้าปากหรือหาว จาก landmark ใบหน้า 68 จุด
4. `lib/distanceAnalysis.ts` เทียบขนาดกรอบใบหน้ากับ baseline ที่ calibrate ไว้
5. `services/faceEnrollment.ts` ส่ง descriptor 128 มิติไปให้ camwell-backend จับคู่ และตรวจซ้ำทุก 3 วินาทีต่อคน

การตรวจใบหน้าทุก 400 ms แทนทุกเฟรมแลกความละเอียดกับความลื่นของหน้าเว็บ
ค่าเริ่มต้นเตือนเมื่อหลับตานาน 2 วินาที (`drowsySustainedMs` ใน `frontend/src/types/wellbeing.ts`) ช่วงนั้นจึงมีการตรวจประมาณ 5 ครั้ง และยังจับได้ทัน
ส่วนการระบุตัวตนตรวจห่างกว่านั้นอีก เพราะคนที่นั่งอยู่ไม่เปลี่ยนตัวกันทุกวินาที

การจับคู่ใบหน้าเกิดที่ camwell-backend ไม่ใช่ในเบราว์เซอร์ เบราว์เซอร์จึงไม่ต้องถือ descriptor ของทุกคนในออฟฟิศ
ถ้ากล้องหลายเครื่องถือ descriptor ไว้เอง ข้อมูลชีวภาพของทุกคนจะกระจายไปทุกเครื่องที่เปิดหน้าไว้

## ทำไมการแจ้งเตือนต้องรอ

`lib/sustainedAlertMachine.ts` เป็น state machine กลางของท่านั่ง ความเหนื่อยล้า และระยะห่างจากจอ
ปัญหาต้องเกิดต่อเนื่องนานเกินเกณฑ์ก่อน ระบบจึงแจ้งเตือนจริง และต้องกลับเป็นปกติสักพักก่อน ระบบจึงเคลียร์การเตือน
ช่วงหน่วงทั้งสองฝั่งนี้เรียกว่า hysteresis

ถ้าไม่มีช่วงหน่วง คนที่ก้มดูโทรศัพท์สามวินาทีจะโดนเตือนทุกครั้ง และค่ามุมที่แกว่งรอบเกณฑ์จะทำให้การเตือนติดดับสลับกัน
การเตือนที่ดังบ่อยเกินไปทำให้คนเลิกสนใจ ผลเสียข้อนี้แย่กว่าการเตือนช้าไปไม่กี่วินาที

การหกล้มไม่ผ่าน state machine นี้ ระบบแจ้งทันทีที่เห็นเหตุการณ์ เพราะคนล้มต้องการความช่วยเหลือทันที ส่วนเตือนพักใช้ตัวจับเวลาของตัวเอง
ทุกเหตุการณ์ใช้โครงสร้าง `AlertEvent` เดียวกันใน `frontend/src/types/alerts.ts`

การแจ้งเตือนแสดงได้สี่แบบ ได้แก่ กรอบหรือ banner สีแดงบนภาพกล้อง banner หกล้มและเตือนพัก เสียงที่ปิดได้ และแถวในตารางเหตุการณ์
`backendAlertReporter` ใน `frontend/src/services/alertReporter.ts` ส่งเหตุการณ์ไปเก็บที่ camwell-backend ตอนเริ่มและตอนจบ

## ข้อจำกัด

- กล้อง IP ที่อยู่ต่าง origin แสดงภาพได้ แต่โมเดลอ่านพิกเซลไม่ได้ เพราะเบราว์เซอร์ taint canvas ตามกฎ CORS
  กล้องแบบนี้ต้องมีตัวกลางแปลงสตรีมให้อยู่ origin เดียวกัน
- เบราว์เซอร์เปิดกล้อง RTSP ตรงๆ ไม่ได้ ระบบ YOLOv8 ไม่มีปัญหานี้ เพราะ yolo-backend อ่าน RTSP ผ่าน go2rtc ได้เอง
- กล้องที่หันหน้าตรงเข้าหาคนมองการยื่นคอและหลังค่อมได้จำกัด เพราะทั้งสองท่าเป็นการเคลื่อนเข้าหากล้อง
  เกณฑ์ปัจจุบันยังต้องปรับจูนจาก dataset จริง
- หน้าเว็บยังไม่มีที่ปรับ `minVisibility` ค่านี้คือ 0.5 และมีผลกับการคำนวณมุม dataset และโครงร่างแบบ full
- ระบบตรวจจับเฉพาะตอนเปิดหน้าค้างไว้ ปิดแท็บแล้วการตรวจจับหยุด
