# แผนแบบ A — Train โมเดลจัดท่านั่งจาก landmark (Posture Classifier)

> สถานะ: **ร่าง — รออนุมัติ ยังไม่เริ่มทำ** (2026-10-06)
> เขียนให้คนที่ไม่เคยทำ machine learning มาก่อนทำตามได้ทีละขั้น — อ่านส่วน "0. คำศัพท์" ก่อนถ้าไม่คุ้น

---

## สรุปสั้น (อ่านอันนี้ก่อน)

- **ปัญหาตอนนี้**: ระบบตัดสินท่านั่งด้วยกฎ "มุมเกินกี่องศา = ท่าไม่ดี" จากการวิเคราะห์ dataset แรก
  (`camwell-dataset-2026-10-05T17-26-57.json`) กฎนี้จับยื่นคอได้ 0–33% และหลังค่อม 0% เพราะกล้องหน้าตรงเห็นท่าพวกนี้
  เป็นมุมเดี่ยวๆ ไม่ชัด — แต่ landmark ที่ได้ชัดดี (visibility ~1.0) ปัญหาจึงอยู่ที่ "การแปลค่า" ไม่ใช่ "การหาจุด"
- **ทางแก้**: สอนโมเดลเล็กๆ ให้ดูหลายค่าพร้อมกัน (ตำแหน่งจุดหัว/ไหล่/สะโพก + ความลึก + มุมเดิม) แล้วทายว่าเป็นท่าไหน
- **โมเดล**: Softmax Logistic Regression (ราว 300 ตัวเลข, ทายครั้งละ < 0.1 ms) — ถ้าไม่พอค่อยลอง MLP เล็ก
- **ข้อมูล**: ใช้ไฟล์จาก Dataset Recorder ที่มีอยู่แล้ว — ต้องการ **อย่างน้อย 4–5 คน × คนละ 2 รอบ × ครบ 5 ท่า**
- **ไม่แตะ**: MediaPipe, กฎเดิม, การแจ้งเตือนของหน้า `/` — โมเดลใหม่จะรัน "คู่ขนาน" ใน Dev Console ให้เทียบก่อน
  จะเปลี่ยนเป็นตัวหลักก็ต่อเมื่อพิสูจน์ด้วยตัวเลขว่าดีกว่า

ภาพรวมขั้นตอน:

```
[1 เก็บข้อมูล] → [2 ตรวจข้อมูล] → [3 แปลงเป็น feature] → [4 train] → [5 วัดผล] → [6 ทดลองคู่ขนานใน console] → [7 ตัดสินใจใช้จริง]
   ผู้ใช้ทำ          สคริปต์           โค้ดใช้ร่วม          สคริปต์       สคริปต์           โค้ด + ผู้ใช้ทดสอบ                ผู้ใช้ตัดสิน
```

## 0. คำศัพท์ (สำหรับมือใหม่)

| คำ | ความหมายในงานนี้ |
|---|---|
| **landmark** | จุดบนร่างกาย 33 จุดที่ MediaPipe หาให้ทุกเฟรม (จมูก หู ไหล่ สะโพก ...) แต่ละจุดมี x, y, z, visibility |
| **sample** | ข้อมูล 1 เฟรม = landmark ทั้งหมด + มุมที่คำนวณได้ + label |
| **label** | คำตอบที่ถูกของ sample นั้น — คือท่าที่เลือกไว้ตอนกดบันทึก (`GOOD`, `FORWARD_HEAD`, `SLOUCH`, `LEAN_LEFT`, `LEAN_RIGHT`) |
| **feature** | ตัวเลขที่ป้อนให้โมเดลดู (เช่น "หัวสูงกว่าไหล่เท่าไหร่") — ได้จากการแปลง landmark |
| **train (ฝึก)** | ให้โมเดลดู feature + label จำนวนมาก จนหาน้ำหนักที่ทายถูกบ่อยที่สุด |
| **น้ำหนัก (weights)** | ตัวเลขที่โมเดลเรียนรู้ได้ เก็บเป็นไฟล์ JSON — นี่คือ "ตัวโมเดล" |
| **test / วัดผล** | ให้โมเดลทายข้อมูลที่ **ไม่เคยเห็นตอน train** แล้วนับว่าถูกกี่ % |
| **overfit** | โมเดลจำข้อมูล train ได้ดีแต่ทายข้อมูลใหม่ผิด — เหมือนท่องข้อสอบเก่าแต่ทำข้อสอบใหม่ไม่ได้ |
| **leave-one-person-out** | วิธีวัดผล: train ด้วยทุกคนยกเว้น 1 คน แล้ว test กับคนนั้น วนจนครบทุกคน — จำลองว่า "เจอพนักงานคนใหม่" |
| **confusion matrix** | ตารางว่าท่าจริง X ถูกทายเป็นท่าอะไรบ้างกี่ % — ดูว่าโมเดลสับสนท่าไหนกับท่าไหน |
| **recall (จับได้)** | ของท่าไม่ดีทั้งหมด โมเดลจับได้กี่ % |
| **false alarm (แจ้งผิด)** | ตอนนั่งท่าดี โมเดลทายว่าไม่ดีกี่ % — ตัวนี้สำคัญมาก เพราะแจ้งผิดบ่อยคนจะเลิกเชื่อระบบ |
| **baseline** | ค่าตอนนั่งท่าดีของคนนั้น (จากปุ่ม Calibrate) — ใช้ทำให้โมเดลไม่ขึ้นกับสรีระแต่ละคน |
| **profile** | ชุดของ "มุมกล้อง + รุ่น Pose" เช่น `webcam-lite`, `imou-full` — ต้อง train แยกกัน |

## 1. เก็บข้อมูล (ผู้ใช้ทำ — ไม่ต้องเขียนโค้ด)

### 1.1 เตรียมก่อนอัด (ทำครั้งเดียวต่อ profile)
1. ตั้งกล้องให้อยู่ **ตำแหน่ง/มุมเดียวกับที่จะใช้งานจริง** แล้วห้ามขยับตลอดการเก็บข้อมูลของ profile นี้
2. เปิด `npm run dev` → เข้า `http://localhost:5173/?console`
   - ต้องรันแบบ dev (`npm run dev`) เท่านั้น — build จริงจะไม่เก็บ sample
3. บน header เลือก:
   - **Pose**: รุ่นเดียวตลอด profile (แนะนำ `full` ถ้าค่า ms ในแถบสถิติไม่เกิน ~60)
   - **ฟีเจอร์ใบหน้า**: ปิด (ไม่จำเป็น และลดภาระเครื่อง)
   - **เสียงแจ้งเตือน**: ปิด (ไม่งั้นจะดังตอนอัดท่าไม่ดี)
   - **โหมด**: Workstation · 1 คน
   - ติ๊ก **Dataset Recorder**
4. ตั้งชื่อ profile ไว้ เช่น `webcam-full` (กล้องหน้าจอ + รุ่น full) — จะใช้ตั้งชื่อไฟล์

### 1.2 อัด 1 รอบ (ต่อ 1 คน) — ใช้เวลาประมาณ 10 นาที
1. ผู้ร่วมทดลองนั่งที่โต๊ะ (ในเฟรมต้องมี **คนเดียว** — ถ้ามีคนเดินผ่าน ระบบจะไม่เก็บช่วงนั้นเอง)
2. ถ้ายังมีข้อมูลค้างในแผง Recorder → กด **Export JSON** เก็บไว้ก่อน แล้วกด **ล้างข้อมูล**
3. อัดทีละท่า **ตามลำดับนี้** (GOOD ต้องมาก่อนเสมอ — สคริปต์จะใช้เป็น baseline ของรอบนี้):

   | ลำดับ | label | วิธีนั่ง | เวลา |
   |---|---|---|---|
   | 1 | `GOOD` | นั่งตัวตรง หลังพิงพนัก หัวตั้งตรงเหนือไหล่ มองจอปกติ | 60 วิ |
   | 2 | `FORWARD_HEAD` | ยื่นคอ/ก้มหน้าเข้าหาจอ เหมือนอ่านตัวหนังสือเล็ก (ลำตัวยังตรง) | 45 วิ |
   | 3 | `SLOUCH` | หลังค่อม ไหล่ห่อ ตัวทรุดลงในเก้าอี้ | 45 วิ |
   | 4 | `LEAN_LEFT` | เอียงตัวไปทางซ้ายของ **ผู้นั่ง** (เช่น เท้าแขนซ้าย) | 45 วิ |
   | 5 | `LEAN_RIGHT` | เอียงตัวไปทางขวาของ **ผู้นั่ง** | 45 วิ |

   แต่ละท่า: เลือก label → นั่งท่านั้นให้เข้าที่ก่อน → กด **● เริ่มบันทึก** → ค้างไว้ตามเวลา → กด **■ หยุดบันทึก**
   - ระหว่างอัด **ขยับเล็กน้อยตามธรรมชาติ** (พิมพ์, หันมองจอ) — อย่านิ่งเป็นรูปปั้น
   - อย่ากดเริ่ม/หยุดถี่ๆ ช่วงละ 2–3 วินาที (ไฟล์แรกเป็นแบบนั้น ทำให้ข้อมูลน้อยและไม่ต่อเนื่อง)
   - ช่วงเปลี่ยนท่า **ต้องหยุดบันทึกก่อน** ค่อยเปลี่ยน label แล้วจัดท่าใหม่ (ไม่งั้นท่าครึ่งๆ กลางๆ จะติด label ผิด)
4. ครบ 5 ท่า → **Export JSON** → เปลี่ยนชื่อไฟล์ตามข้อ 1.3 → **ล้างข้อมูล**

### 1.3 ตั้งชื่อไฟล์ (สำคัญ — สคริปต์อ่านข้อมูลจากชื่อไฟล์)
```
<profile>__<รหัสคน>__<รอบ>.json
ตัวอย่าง:  webcam-full__P01__S1.json
           webcam-full__P01__S2.json
           webcam-full__P02__S1.json
```
- **รหัสคน** ใช้ `P01`, `P02` ... (ห้ามใช้ชื่อจริง) — จดคู่ชื่อ↔รหัสไว้ที่อื่นที่ปลอดภัย
- **รอบ** `S1`, `S2` ... (คนเดิมต่างวัน/ต่างเสื้อ/ต่างแสง)
- เก็บไว้ในโฟลเดอร์ `data/datasets/` ของโปรเจกต์ (จะเพิ่มเข้า `.gitignore` — **ไม่ commit ข้อมูลคนลง git**)

### 1.4 ต้องเก็บเท่าไหร่
| ระดับ | จำนวน | ใช้ทำอะไรได้ |
|---|---|---|
| ขั้นต่ำ | 4 คน × 2 รอบ | train + วัดผลแบบ leave-one-person-out ได้ (ผลยังแกว่ง) |
| แนะนำ | 6–8 คน × 2–3 รอบ | ตัวเลขเชื่อถือได้พอตัดสินใจ |

- **ความหลากหลายสำคัญกว่าความยาว**: คนต่างส่วนสูง/รูปร่าง, เสื้อต่างสี, แว่น/ไม่แว่น, ผมยาว/สั้น, แสงเช้า/บ่าย
- 12 sample/วินาที แทบเหมือนกันหมด — อัดยาวกว่าที่ตารางบอกไม่ได้ช่วยมาก

### 1.5 ขอความยินยอม
- แจ้งผู้ร่วมทดลองว่าเก็บ **ตัวเลขตำแหน่งร่างกาย ไม่เก็บภาพ** เพื่อปรับปรุงระบบตรวจท่านั่ง และขอลบข้อมูลของตัวเองได้
- ใครขอลบ → ลบไฟล์ที่มีรหัสคนนั้นทั้งหมด แล้ว train ใหม่

## 2. ตรวจข้อมูลก่อน train (สคริปต์ — ผมทำ)

`scripts/ml/check-datasets.mjs` (ต่อยอดจากสคริปต์วิเคราะห์ที่ใช้กับไฟล์แรก) รันด้วย:
```bash
node scripts/ml/check-datasets.mjs data/datasets
```
จะรายงานต่อไฟล์:
- ชื่อไฟล์ถูกรูปแบบไหม · `meta.poseModel` ตรงกับ profile ไหม · ทุกไฟล์ใน profile เดียวกันใช้รุ่นเดียวกันไหม
- แต่ละ label มีกี่วินาที — **เตือนถ้าขาด label หรือ < 20 วินาที** · มี GOOD อยู่ก่อนท่าอื่นไหม
- สัดส่วน `full_body` / `upper_body` · visibility ของหู/ไหล่/สะโพก
- ค่ามุมแต่ละท่า (p10 / median / p90) ให้ดูด้วยตาว่าท่าต่างกันจริง

**ผู้ใช้ทำ**: อ่านรายงาน ถ้ามีไฟล์ไหนถูกเตือน → อัดรอบนั้นใหม่

## 3. แปลงข้อมูลเป็น feature (โค้ดใช้ร่วมกันตอน train และตอนใช้งานจริง)

**กฎเหล็ก**: ตอน train และตอนรันจริงต้องใช้ **ฟังก์ชันเดียวกัน** แปลง landmark → feature
ถ้าเขียนสองที่แล้วต่างกันนิดเดียว โมเดลจะทายเพี้ยนโดยไม่มี error ให้เห็น

ไฟล์ใหม่ `src/lib/postureClassifierFeatures.ts` ฟังก์ชัน `buildClassifierFeatures(sample, baseline)` คืน array ตัวเลขลำดับคงที่:

| กลุ่ม | รายละเอียด | จำนวนโดยประมาณ |
|---|---|---|
| A. ตำแหน่งจุดช่วงบน (ภาพ 2D) | จุด 0–12 (หน้า+ไหล่) และ 23–24 (สะโพก): x, y **ลบด้วยกึ่งกลางไหล่ แล้วหารด้วยความกว้างไหล่** → ไม่ขึ้นกับว่านั่งตรงไหนของภาพ/ห่างกล้องแค่ไหน | 15 จุด × 2 = 30 |
| B. ความลึก (world) | z ของจุดเดียวกันจาก `worldLandmarks` ลบด้วย z กึ่งกลางไหล่ (หน่วยเมตร) — ช่วยเห็นการยื่นหัว/ค่อมไปข้างหน้า | 15 |
| C. มุมเดิม | `neckAngleDeg`, `torsoAngleDeg`, `shoulderTiltDeg`, `headHeightRatio` | 4 |
| D. ส่วนต่างจาก baseline | มุม C ลบค่าของ baseline (ตอน train = median ของ GOOD ในรอบเดียวกัน, ตอนใช้งาน = ค่าจากปุ่ม Calibrate) | 4 |
| E. ตัวบอกข้อมูลขาด | 1/0 ว่าสะโพกมองเห็นไหม · ค่าที่เป็น null แทนด้วย 0 | 2 |

หมายเหตุ:
- ไม่ใช้แขน/ขา (มักโดนโต๊ะบังหรืออยู่นอกเฟรม)
- กลุ่ม D ใช้ได้เฉพาะ 4 ค่าที่ baseline จาก Calibrate มีจริง (`PostureBaseline`) — **ตอนใช้งานจริงจึงต้อง Calibrate ก่อน**
  ถ้ายังไม่ Calibrate ระบบจะใช้กฎเดิมแทน
- `LEAN_LEFT` / `LEAN_RIGHT` ต้องแยกซ้ายขวาได้ → feature กลุ่ม A มีทิศอยู่แล้ว (x ของหู/จมูกเทียบกึ่งกลางไหล่)
  แต่ระวัง: ภาพจากกล้องในเครื่อง **ถูก mirror ตอนแสดงผล แต่ landmark ไม่ได้ mirror** — สคริปต์จะใช้ค่าจาก landmark ตรงๆ ทั้ง train และใช้งาน จึงสอดคล้องกันเอง
- มี unit test: ป้อน sample ตัวอย่าง → ได้ feature ตามที่คำนวณมือไว้ + ย้าย/ขยายคนในภาพแล้วกลุ่ม A ต้องไม่เปลี่ยน

## 4. Train (สคริปต์ — ผมทำ, ผู้ใช้รัน)

`scripts/ml/train-posture-classifier.ts` รันด้วย:
```bash
npm run ml:train -- --profile webcam-full
```

ขั้นตอนข้างในสคริปต์ (อธิบายให้เข้าใจ ไม่ต้องทำเอง):
1. **อ่านไฟล์** ทุกไฟล์ของ profile ใน `data/datasets/` → รู้ว่าแต่ละ sample เป็นของคนไหน รอบไหน จากชื่อไฟล์
2. **ลดข้อมูลซ้ำ**: เก็บแค่ ~3 sample ต่อวินาที (ทิ้งเฟรมที่ติดกันเกือบเหมือนเดิม) — กันโมเดลจำเฟรมซ้ำ และทำให้ train เร็ว
3. **คำนวณ baseline ต่อรอบ** = median ของ GOOD ในไฟล์นั้น → ใช้ทำ feature กลุ่ม D
4. **แปลงเป็น feature** ด้วยฟังก์ชันจากข้อ 3
5. **ปรับสเกล (standardize)**: แต่ละ feature ลบค่าเฉลี่ยแล้วหารส่วนเบี่ยงเบน — ให้ทุกค่าอยู่ช่วงพอๆ กัน (เก็บค่าเฉลี่ย/ส่วนเบี่ยงเบนไว้ในไฟล์โมเดลด้วย ตอนใช้งานต้องปรับแบบเดียวกัน)
6. **ถ่วงน้ำหนักท่า**: ถ้าท่าไหนมีข้อมูลน้อยกว่า ให้น้ำหนักมากขึ้น ไม่ให้โมเดลเอียงไปทาย GOOD ตลอด
7. **Train Softmax Logistic Regression** ด้วย gradient descent + L2 regularization (กัน overfit)
   - ค่าตั้งต้น: learning rate 0.1, 500 รอบ, L2 = 0.01 (ปรับได้ด้วย flag)
8. **วัดผลแบบ leave-one-person-out** (ข้อ 5) แล้ว **train รอบสุดท้ายด้วยทุกคน** → เขียนไฟล์โมเดล

เหตุผลที่เขียน train เอง (ไม่ใช้ Python/scikit-learn): เครื่องนี้ไม่มี Python และ logistic regression เขียนเองได้ใน ~100 บรรทัด
ข้อ 3 กับข้อ 4 ต้อง import โค้ด TypeScript จาก `src/lib/` → ต้องเพิ่ม dev dependency **`tsx`** (ตัวรัน TypeScript) 1 ตัว — ดูคำถามข้อ 9

## 5. วัดผล — โมเดลดีพอไหม

สคริปต์ train พิมพ์รายงาน + เขียน `data/reports/<profile>-<วันที่>.md`:
- **ต่อคนที่ถูกกันออก**: accuracy, false alarm, recall ของแต่ละท่า
- **confusion matrix รวม**
- **เทียบกับกฎเดิม** บนข้อมูลชุดเดียวกัน (ใช้ `classifyPosture` จริง + baseline แบบเดียวกัน)

เกณฑ์ผ่าน (ตั้งต้น — ปรับได้เมื่อเห็นข้อมูลจริง):
| ตัวชี้วัด | เป้า |
|---|---|
| False alarm ตอนนั่ง GOOD | ≤ 5% |
| Recall ท่าไม่ดีเฉลี่ย | ≥ 80% |
| ทุกคนที่ถูกกันออก | ไม่มีใครต่ำกว่าเกณฑ์มากผิดปกติ (ถ้ามี = ข้อมูลไม่พอ/ไม่หลากหลาย) |
| เทียบกฎเดิม | ดีกว่าชัดเจนทั้งสองตัวแรก |

**ถ้าไม่ผ่าน** (ทำตามลำดับ):
1. ดู confusion matrix ว่าสับสนท่าไหน → เก็บข้อมูลท่านั้นเพิ่ม/อธิบายท่าให้ผู้ร่วมทดลองชัดขึ้น
2. เพิ่มคนให้หลากหลายขึ้น
3. ลอง MLP เล็ก (`--model mlp`) — เฉพาะเมื่อมีข้อมูล ≥ 6 คนแล้ว

## 7. ตัดสินใจใช้จริง (ผู้ใช้ตัดสิน — แผนแยก)

## 11. คำถามที่มักเจอ

- **ทำไมไม่ train MediaPipe เองให้แม่นขึ้น?** — MediaPipe ไม่เปิดให้ train ต่อ และ landmark ที่ได้ชัดดีอยู่แล้ว ปัญหาอยู่ที่การแปลค่า (ดู "สรุปสั้น")
- **ต้องใช้ GPU ไหม?** — ไม่ต้อง โมเดลเล็กมาก train บน CPU เครื่องนี้เสร็จในไม่กี่วินาที–นาที
- **ข้อมูลคนเดียวพอไหม?** — ไม่พอ โมเดลจะจำสรีระคนนั้น แล้วทายคนอื่นผิด
- **เปลี่ยนตำแหน่งกล้องแล้วต้องทำใหม่ไหม?** — ถ้าเปลี่ยนมุมมาก ใช่ (นับเป็น profile ใหม่) ขยับเล็กน้อยให้ Calibrate ใหม่ก็พอ
- **เปลี่ยนรุ่น Pose แล้วใช้โมเดลเดิมได้ไหม?** — ไม่ได้ ต้อง train ต่อรุ่น (dataset ล็อกรุ่นอยู่แล้ว และ console จะเตือนถ้าไม่ตรง)
- **โมเดลจะรู้ไหมว่าใครนั่ง?** — ไม่ รู้แค่ตำแหน่งร่างกาย ไม่ใช้ใบหน้า
